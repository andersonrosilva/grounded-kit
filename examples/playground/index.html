TypeScript · Node ≥ 22 · pnpm

Um motor de IA reutilizável, agnóstico de domínio

O grounded-kit (pacote ai-kit) orquestra retrieve → generate → validate → moderate com saída estruturada (Zod), guardrails e RAG. O domínio entra por um domain pack; o motor nunca o conhece.

Estado atual: esqueleto didático. Tipos, assinaturas e exports existem (e o pnpm build funciona), mas toda função em src/ ainda lança not implemented. Por isso o playground roda uma simulação de referência (mock) escrita em JS puro que segue o roteiro documentado em cada módulo — não é o código do kit. Os trechos do passo a passo são TypeScript real, checado contra os tipos do src/.

O fluxo de uma chamada

Cada pipeline.run(pack, input) percorre estas etapas e termina em um de três resultados.

  1. 0EntradaTIn definido pelo pack
  2. 1PREGuardrails pre. block não chama o modelo
  3. 2RETRIEVERAG: toQuery → embeddings → store.query(topK)
  4. 3GENERATE ⇄ VALIDATEaté maxAttempts; erros viram feedback
  5. 4POSTGuardrails post; modify é revalidado
  6. ✓RunResultok · blocked · invalid
ok → data validada + usage blocked → guardrail vetou (pre ou post) invalid → esgotou as tentativas ProviderError → exceção (infra), não consome tentativa

Motor × domínio

O kit (motor)

Só contratos (ports) e orquestração. Nada de domínio.

  • Provider — gera texto (Ollama, Gemini ou o seu)
  • Embeddings + VectorStore — RAG (memória ou pgvector)
  • Guardrail, Validator, Tracer — pontos de encaixe
  • createPipeline — o orquestrador

O domain pack (você)

Declarado com definePack; é onde mora a política.

  • Schema Zod de saída e prompts
  • Base de conhecimento + toQuery
  • Validators (fatos por dado) e guardrails (política)
  • Exemplo no repo: examples/nutrition-pack (receitas)

Regras críticas

Instalação rápida

O que acontece hoje se você importar o kit: o build gera todos os subpaths, mas chamar definePack(...) lança Error: not implemented (verificado contra o dist/). A ordem de implementação está no README.md da raiz (passos 1 a 6).

Passo a passo de consumo

Do zero até o primeiro pipeline.run, com o pack de receitas/nutrição como exemplo. Todos os trechos são TypeScript que compila contra os tipos reais do kit.

Playground

Configure o pack, roteirize as respostas do modelo e veja o pipeline decidir. O resultado atualiza sozinho a cada mudança.

MODO MOCK Nenhuma API, chave ou rede é usada. O “modelo” é um FakeProvider roteirizado por você e os embeddings são um fake determinístico; o pipeline é a reimplementação de referência (kit-sim.js), não o src/ do kit.
